# Отчет по исправлению багов (Task Manager API)

В ходе выполнения задания в исходном коде файла `app.py` было найдено и исправлено **9 дефектов** (8 пронумерованных багов, один из которых разделен на два пункта).

## Список исправленных багов

### 1. Фильтрация задач (BUG 1a и 1b)
**Проблема:** В эндпоинте `GET /api/tasks` были перепутаны фильтры. При запросе `status=active` возвращались выполненные задачи (`completed = 1`), а при `status=completed` — активные (`completed = 0`).
**Решение:** Исправлены условия в SQL-запросе: для `active` теперь `completed = 0`, для `completed` — `completed = 1`.

### 2. Пагинация (BUG 2)
**Проблема:** В запросе использовалось `LIMIT per_page - 1`. Из-за этого на каждой странице возвращалось на одну задачу меньше, а при `per_page = 1` запрос вообще возвращал пустой список.
**Решение:** Изменено на `LIMIT per_page`. Дополнительно добавлена валидация параметров `page` и `per_page` и ограничение максимального размера страницы (100).

### 3. SQL-инъекция в поиске (BUG 3)
**Проблема:** В `GET /api/tasks/search` параметр `q` подставлялся напрямую в строку SQL-запроса через f-строку.
**Решение:** Запрос переписан на параметризованный (`LIKE ?`). Также добавлено экранирование спецсимволов `%` и `_`, чтобы поиск работал корректно.

### 4. Валидация при создании (BUG 4)
**Проблема:** В `POST /api/tasks` не проверялось поле `title`. Можно было создать задачу с пустым названием или пробелами.
**Решение:** Добавлена проверка `title.strip()`. Если поле пустое — возвращается ошибка `400 Bad Request`. Также добавлена валидация `priority`.

### 5. HTTP-статус при создании (BUG 5)
**Проблема:** При успешном создании задачи возвращался статус `200 OK`.
**Решение:** Исправлено на правильный статус `201 Created`.

### 6. Критический баг в обновлении (BUG 6)
**Проблема:** В `PUT /api/tasks/<id>` при обновлении статуса `completed` отсутствовало условие `WHERE id = ?`. Запрос обновлял статус **всех** задач в базе данных.
**Решение:** Добавлено условие `WHERE id = ?`. Также добавлена проверка существования задачи.

### 7. Логика удаления (BUG 7)
**Проблема:** Эндпоинт `DELETE /api/tasks/<id>` не удалял задачу, а просто помечал её как выполненную (`completed = 1`).
**Решение:** Заменено на реальное удаление из БД (`DELETE FROM tasks WHERE id = ?`). Добавлена проверка на `404 Not Found`.

### 8. Статистика (BUG 8)
**Проблема:** В `GET /api/stats` показатель `rate` возвращался в виде доли (от 0 до 1), а не в процентах.
**Решение:** Формула изменена на `(completed / total * 100)`. Добавлено округление до двух знаков.

## Дополнительные улучшения
- Все SQL-запросы переведены на параметризацию для защиты от инъекций.
- Добавлена обработка ошибок ввода (неверные типы данных в query-параметрах).
