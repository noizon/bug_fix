# Фикс багов в Task Manager API

Порылся в коде `app.py`, нашел и исправил кучу косяков. Всего вышло 9 дефектов (по нумерации 8, но первый там разбит на два). Ниже расписал, что было не так и как починил.

## Что было сломано:

1. **Фильтры в /api/tasks (баг 1a и 1b):** 
   Там была тупо перепутана логика. При запросе `active` возвращались выполненные задачи, а при `completed` — наоборот, активные. Поменял нули и единицы местами, теперь все как надо.

2. **Пагинация (баг 2):** 
   В SQL-запросе стояло `LIMIT per_page - 1`. Из-за этого на страницу выводилось на одну задачу меньше, а если ставишь `per_page=1`, то вообще пустота приходит. Убрал этот минус. Еще добавил проверку на дурака, чтобы `page` и `per_page` были нормальными числами и не больше 100.

3. **Дыра в поиске (баг 3):** 
   В `/api/tasks/search` переменная `q` подставлялась прямо в строку запроса. Это классическая SQL-инъекция, можно было всю базу слить. Переделал на параметризованный запрос (`LIKE ?`) и добавил экранирование символов `%` и `_`.

4. **Создание задачи без названия (баг 4):** 
   Можно было отправить POST-запрос с пустым `title` и в базу падала пустая строка. Добавил `strip()` и проверку: если пусто — отдаем 400 ошибку. Заодно проверил, чтобы `priority` был числом.

5. **Неправильный статус (баг 5):** 
   При создании задачи отдавался 200 OK. По стандарту REST для создания нужен `201 Created`. Поменял.

6. **Критичный баг в PUT (баг 6):** 
   В `update_task` при обновлении поля `completed` забыли `WHERE id = ?`. В итоге один запрос обновлял статус **вообще у всех задач** в базе. Дописал условие, теперь меняется только нужная.

7. **Удаление, которого нет (баг 7):** 
   В `DELETE` запросе вместо реального удаления просто ставился `completed = 1`. То есть задачи висели в базе как зомби. Переделал на честный `DELETE FROM tasks WHERE id = ?` и добавил проверку на 404, если такого id нет.

8. **Кривая статистика (баг 8):** 
   В `/api/stats` считался `rate`, но возвращался как доля от 0 до 1. Сделал умножение на 100 и `round()`, чтобы отдавались нормальные проценты.

## Что еще поправил по ходу:
- Все запросы к БД перевел на параметризацию, чтобы никаких инъекций.
- Убрал `try/except`, который в поиске глотал ошибки и возвращал их как строку.
- Немного почистил код и расставил комментарии `# FIX N` в местах изменений.
